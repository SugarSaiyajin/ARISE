## 優先評估的改進

### 1. 角色作業狀態與動作回饋

目前 game.gd 的 `_work` 先呼叫 `state.work` 扣體力、改田地，再播放 0.30 秒工具動畫。一般移動流程沒有用 `action_age` 鎖定角色。因此可以研究明確的待機、移動、作業狀態，讓角色與工具動作更一致。

若教學提供相應內容，先針對一種工具做小範圍實作。需明確選定操作當下結算或動畫落點結算，並驗證長按、不重複扣料、轉向、進屋、背景中斷及存讀檔，不直接把所有操作延後到動畫結束。

### 2. 可在編輯器配置的地圖

目前地圖使用 PNG 底圖與 GDScript 即時繪製，障礙物、互動範圍、標籤及圖集座標多為常數。這適合小型原型，但擴大城鎮與調整建築時需要同步改數個位置。

若教學包含地圖編輯，可評估 Godot 4.6 的 TileMapLayer、自訂場景及可配置互動點。先用一張隔離試驗地圖驗證，不一次替換五張地圖。保留 AStar、點標籤尋路、安全出生點及舊位置復原規則。教學使用的 Godot 版本尚不明，不假定其 TileMap API 能原樣使用。

### 3. 作物與物品資料擴充

目前作物定義在 FarmState.CROPS，種子、收成與存檔驗證列舉三種作物；加工、養雞、釣魚與料理則各自有資料腳本。未來增加作物，需要同步維護資料、圖集、商店及舊檔預設值。

若教學使用 Resource 或統一物品定義，可先抽出作物資料，維持現有字串 ID，為舊存檔補齊新增作物。先驗證原有三種作物行為完全相同，再擴大春季內容。通用背包或拖曳交換需另行設計手機操作，不能假定滑鼠拖曳可直接移植。

### 4. 居民作息

現有青禾、洛安與雷恩使用固定位置，尚未提供每日移動作息。若教學有 NPC 日程，可與遊戲內時鐘整合，增加鎮上生活感。

實作前須處理暫停、切區、夜間、存讀檔，以及接單後居民換位置仍能找到並交付。這是內容擴充，優先序在操作手感與地圖製作流程之後。
